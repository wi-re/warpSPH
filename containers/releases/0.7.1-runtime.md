# Smaller 0.7.1 deployment images

The initial development-base image is retained as historical evidence. The
runtime recipe takes exact Torch/CUDA/NCCL binaries from the same pinned NGC
26.01 bases and copies them into a clean Ubuntu 24.04 final image. Application
source fingerprints and versions match the original 0.7.1 checkpoint.

## Measured sizes

Sizes below use decimal GB. Download bytes are measured on completed archives,
not Docker's local content-store accounting.

| amd64 Docker | Initial | Runtime | Reduction |
| --- | ---: | ---: | ---: |
| Portable compressed archive | 9.632 GB | 4.031 GB | 58.1% |
| Uncompressed layers (`docker history --human=false`) | 22.605 GB | 8.068 GB | 64.3% |

The ARM64 SIF is **3.443 GB**, versus 9.495 GB before (63.7% smaller). Its
self-contained Isambard tar is **3.506 GB**, versus 9.517 GB (63.2% smaller).
The SIF uses XZ-compressed SquashFS; its reader/startup is part of the renewed
site gate.

The numerical/visualization dependencies still dominate the remaining size.
The image retains the Remote companion, video support, CUDA JIT, matching
functorch/Triton, PTX assembler and host/Python/CUDA headers for compilation
operators. Numerical defaults from NGC, including the TF32 override, are retained.
Venv interpreter copies preserve the companion environment when resolving paths.
CUDA aliases resolve directly to exported files, without distro alternatives.
CUDA forward-compat libraries and NVIDIA's activation check remain because
the accepted Isambard communication provenance maps that libcuda path.
Compatibility drivers are not registered in the global linker cache.

Native symbols are removed from 72 libraries, saving 913,240,760 bytes; allocated
ELF section contents, addresses and sizes must remain identical for every
transformed binary. Original and runtime hashes are recorded in
`/opt/warpsph/runtime-export.json`. Compatibility-driver files remain unchanged.
The separate C++ development branch is excluded.

## Rebuild

Use `scripts/build_container.py --runtime-image ubuntu@sha256:fe81560990fae86dc4743202b2cb4d3df98d0bcf949173cecef15ce1127ef852`
with the existing source, architecture-specific NGC base and dependency pins.
The frozen `amd64-release-context` / `arm64-release-context` directories record
the payload build inputs; **apply `config-context` afterwards** for these exact
artifacts. `final-config.json` records both image IDs, configuration/alias files,
executable hashes and numerical defaults. The Isambard tar includes the ARM64
overlay as `config-overlay`. Current repository recipes incorporate those fixes
directly and do not require the extra overlay. Select `containers/Dockerfile.runtime`, pass both `BASE_IMAGE`
and `RUNTIME_IMAGE`, and use the same platform/Warp version/target as the manifest.
The original `Dockerfile` and existing build invocations remain available.
See [build options](../README.md) and [original release provenance](0.7.1.md).

## Usage and checksums

```bash
docker load -i warpsph-0.7.1-runtime-amd64.docker.tar.gz
docker run --rm --gpus all -v "$PWD:/work" warpsph:0.7.1 help
```
